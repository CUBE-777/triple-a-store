# Triple A Store — دليل الإعداد والتشغيل

متجر إلكتروني **مستقل** مرتبط بعلامة Triple A Studio، مبني بـ HTML + CSS + JavaScript عادي (بدون React أو أي أداة بناء)، مع Supabase (حسابات + قاعدة بيانات + تخزين صور) وNetlify (استضافة). الطلبات تُرسل عبر واتساب. **لا يوجد دفع داخل الموقع.**

> الحالة الحالية: الكود مكتوب ومُختبَر محلياً (انظر `TEST-REPORT.md`)، لكنه **لم يُجرَّب بعد على مشروع Supabase حقيقي** لأنني لا أملك بياناتك. اتبع قسم «قائمة التحقق قبل الإطلاق» في آخر هذا الملف بعد الإعداد.

---

## 0) هيكل المشروع

```
triple-a-store/
├─ index.html        الصفحة الرئيسية (الأقسام + الفلاتر + البحث + المنتجات)

├─ cart.html         السلة وإرسال الطلب عبر واتساب
├─ admin.html        لوحة الإدارة (تتطلب تسجيل دخول مسؤول)
├─ 404.html          صفحة غير موجودة
├─ css/store.css     كل التنسيقات (نفس ألوان وخطوط Triple A Studio)
├─ js/
│  ├─ config.js      ⭐ الملف الوحيد الذي تعدّله للإعداد (Supabase + واتساب + الروابط)
│  ├─ i18n.js        ⭐ كل نصوص الواجهة بثلاث لغات (عربي/فرنسي/إنجليزي)
│  ├─ common.js      اللغة + الثيم + الهيدر والفوتر + أدوات مشتركة
│  ├─ cart-core.js   منطق السلة ورسالة واتساب (قابل للاختبار)
│  ├─ api.js         قراءة البيانات العامة من Supabase

│  ├─ admin.js       لوحة الإدارة
│  ├─ admin-orders.js  (إضافة) تبويب الطلبات في الإدارة
│  ├─ orders.js        (إضافة) تسجيل الطلب عند الضغط على زر واتساب
│  ├─ lightbox.js      (إضافة) تكبير صور المنتج
│  └─ demo-data.js   بيانات تجريبية (خاملة إلا إذا فعّلت DEMO_MODE)
```

المتجر **لا يعتمد على أي ملف من موقع Triple A Studio**؛ التشابه بصري فقط (نسخنا الألوان والخطوط والشعار).

## 1) تشغيل المتجر محلياً

يلزمك Python 3.11+ (أو أي خادم ملفات). افتح الطرفية داخل مجلد المشروع:

```bash
python3 tests/serve.py 8080
```

ثم افتح `http://localhost:8080`. (يمكنك أيضاً استعمال إضافة Live Server في VS Code.) لا تفتح الملفات بالنقر المزدوج؛ استعمل خادماً.

**تجربة الشكل قبل إعداد Supabase:** في `js/config.js` ضع `DEMO_MODE: true`. ستظهر 9 منتجات وهمية مع شريط أصفر «وضع تجريبي». في هذا الوضع **لوحة الإدارة معطّلة**. ⚠ أعده إلى `false` قبل النشر.

---

## 2) إنشاء مشروع Supabase

1. أنشئ حساباً في <https://supabase.com> ثم **New project**. اختر منطقة قريبة (مثلاً Frankfurt أو Paris) وضع كلمة مرور لقاعدة البيانات (احفظها عندك فقط).
2. من **Project Settings → API** انسخ:
   - **Project URL** (مثل `https://abcd1234.supabase.co`)
   - **anon / publishable key** (المفتاح العام).
3. ضعهما في `js/config.js`:
   ```js
   SUPABASE_URL: "https://abcd1234.supabase.co",
   SUPABASE_ANON_KEY: "المفتاح-العام",
   ```

> 🔐 المفتاح العام **مصمَّم ليكون ظاهراً** في المتصفح؛ الأمان يأتي من سياسات RLS. أما مفتاح **service_role** (أو `sb_secret_…`) فهو سري تماماً: **لا تضعه في أي ملف من هذا المشروع ولا ترسله لأحد.** المشروع لا يحتاجه إطلاقاً، وسكربت `generate-config.mjs` يرفضه تلقائياً.

## 3) تنفيذ ملفات قاعدة البيانات (Migrations)

من لوحة Supabase افتح **SQL Editor → New query**، ثم الصق محتوى كل ملف **بهذا الترتيب** واضغط Run (كلها آمنة لإعادة التشغيل):

| الترتيب | الملف | ماذا يفعل |
|---|---|---|
| 1 | `supabase/migrations/001_schema.sql` | الجداول والقيود والفهارس |
| 2 | `supabase/migrations/002_rls_policies.sql` | سياسات الأمان (RLS) |
| 3 | `supabase/migrations/003_storage.sql` | حاويتا التخزين وسياساتهما |
| 4 | `supabase/migrations/004_seed_categories.sql` | (اختياري) 6 أقسام مبدئية — لا منتجات وهمية |
| 5 | `supabase/migrations/005_orders.sql` | (اختياري) سجل الطلبات في لوحة الإدارة (القسم 10-ب) |

**الجداول:** `categories` + `category_translations`، `products` + `product_translations`، `product_private` (مورّد/تكلفة/الملف الرقمي الخاص — للإدارة فقط)، `admin_users`. جداول الطلبات (`orders`, `order_items`) اختيارية وتُنشأ بالملف 005 فقط (القسم 10-ب).

**ماذا تفرضه القاعدة بنفسها (وليس المتصفح فقط):** نوع المنتج من ثلاثة فقط؛ العملة MAD فقط؛ السعر ≥ 0 ولا يكون فارغاً إلا للخدمة «بعرض سعر»؛ المخزون للمنتجات المادية فقط وبكمية صحيحة؛ المنتج الرقمي يتطلب طريقة تسليم؛ صيغة slug محددة؛ أطوال النصوص؛ حد أقصى 8 صور و5 خيارات.

## 4) إعداد المصادقة (Authentication)

1. **Authentication → Sign In / Providers → Email**: اترك تسجيل الدخول بالبريد وكلمة المرور مفعّلاً.
2. **أوقف إنشاء الحسابات الذاتي**: عطّل خيار **Allow new users to sign up** (في نفس الصفحة أو ضمن Sign In / Providers). بهذا لا يستطيع أي زائر إنشاء حساب. (حتى لو أُنشئ حساب، فهو **ليس مسؤولاً** لأن الصلاحية تأتي من جدول `admin_users` فقط.)
3. المتجر لا يوفّر صفحة تسجيل عامة ولا نقطة «إنشاء مسؤول» في الواجهة.

> الأسماء في لوحة Supabase تتغير أحياناً؛ إن لم تجد الخيار بنفس الاسم فابحث عن إعداد «sign ups / signups» داخل Authentication.

---

## 5) إنشاء أول مسؤول (بأمان)

1. **Authentication → Users → Add user → Create new user**: اكتب بريدك وكلمة مرور **قوية** وفعّل **Auto Confirm User**. (كلمة المرور تكتبها أنت داخل لوحة Supabase فقط.)
2. افتح `supabase/create_first_admin.sql`، غيّر البريد داخله إلى بريدك، والصقه في **SQL Editor** ونفّذه. يجب أن يظهر صف واحد في النتيجة.
3. افتح `admin.html` وسجّل الدخول.

لإضافة مسؤول ثانٍ: أنشئ مستخدماً ثم نفّذ نفس الاستعلام ببريده. لإزالة مسؤول: `delete from public.admin_users where user_id = '...';`

## 6) التخزين (Storage) والصلاحيات

نفّذ `003_storage.sql` (القسم 3) فتُنشأ حاويتان:

| الحاوية | الوصول | الاستعمال |
|---|---|---|
| `product-images` | **عامة للقراءة** (حتى تظهر الصور للزوار). الرفع/التعديل/الحذف للمسؤول فقط. حد 5MB، JPG/PNG/WebP | صور المنتجات |
| `digital-files` | **خاصة تماماً**، لا يقرؤها أحد إلا المسؤول. حد 50MB للملف (حد الخطة المجانية) | الملفات الرقمية المدفوعة |

**كيف يعمل التسليم الآمن للمنتجات الرقمية (متوافق مع الخطة المجانية):** تحمّل الملف من نموذج المنتج (يذهب إلى الحاوية الخاصة)، وعندما يدفع العميل وتتحقق أنت من الدفع: افتح المنتج → **«إنشاء رابط تحميل مؤقت (24 ساعة)»** → انسخ الرابط وأرسله عبر واتساب. ينتهي الرابط تلقائياً. لا يوجد رابط عام دائم أبداً.

**تحسين الصور تلقائياً:** قبل الرفع تُصغَّر الصورة إلى 1600px كحد أقصى وتُحوَّل إلى WebP (جودة 82%) لتوفير مساحة التخزين المجاني.

للتحقق: **Storage** في Supabase يجب أن يُظهر الحاويتين، و`digital-files` عليها وسم Private.

## 7) متغيرات البيئة

المتجر موقع ثابت بلا خادم، لذلك لديك طريقتان:

**الطريقة أ (الأبسط — موصى بها):** عدّل `js/config.js` مباشرة (القسم 2). مناسبة أيضاً للنشر بالسحب والإفلات.

**الطريقة ب (اختيارية):** اضبط متغيرات في Netlify (Site configuration → Environment variables) بأسماء المذكورة في `.env.example` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `WHATSAPP_NUMBER`, `STORE_URL`, `STUDIO_URL`, `CONTACT_EMAIL`)، فيكتبها سكربت `scripts/generate-config.mjs` في `config.js` أثناء البناء. تعمل فقط مع النشر عبر Git (وليس السحب والإفلات). بعد أي تغيير أعد النشر.

لا تنشر أي ملف `.env` حقيقي؛ `.gitignore` يمنعه.

## 8) النشر على Netlify (موقع منفصل)

1. ارفع مجلد `triple-a-store` إلى مستودع Git **منفصل** (مثلاً `triple-a-store` على GitHub). لا تضعه داخل مستودع الموقع الأصلي.
2. في Netlify: **Add new site → Import an existing project** → اختر المستودع. إعدادات البناء تُقرأ من `netlify.toml` (Publish directory = `.`). هذا **موقع Netlify جديد** ولا يمس موقع Triple A Studio ولا إعداداته.
   - بديل بلا Git: **Add new site → Deploy manually** واسحب المجلد (عندها عدّل `config.js` يدوياً أولاً).
3. بعد النشر ستحصل على رابط مثل `https://اسم-موقعك.netlify.app`. هذا هو **رابط المتجر**.
4. ضعه في `STORE_URL` داخل `config.js` (بدون `/` في النهاية) فتُفعَّل روابط canonical. **لا تضع دومين غير موجود.** وإن اشتريت دومين لاحقاً فغيّره هناك.
5. `netlify.toml` يضيف ترويسات أمان وCSP. ⚠ إن استعملت **دومين مخصصاً لـ Supabase** أضفه في `connect-src` و`img-src` داخل `netlify.toml`.

## 9) ربط موقع Triple A Studio الأصلي بالمتجر

أجرينا **أصغر تعديل ممكن** على الموقع الأصلي: 12 سطراً في 3 ملفات (`data.js`, `script.js`, `site.js`)، موجودة جاهزة في المجلد `original-site-patch/` مع ملف الفروقات `store-link.patch` وشرحه. الملفات الأصلية في أرشيفك الأصلي لم تُلمس.

الفكرة: رابط «المتجر / Boutique / Store» **يظهر في قائمة الموقع والتذييل فقط بعد** أن تضع رابط المتجر في `storeUrl` داخل `data.js`؛ وقبل ذلك لا يتغير الموقع الأصلي إطلاقاً (تحققنا أن القائمة مطابقة حرفياً للأصل).

الخطوات:
1. انسخ الملفات الثلاثة من `original-site-patch/` فوق ملفاتك في مشروع الموقع الأصلي (بعد أخذ نسخة احتياطية).
2. في `data.js` اضبط: `storeUrl: "https://رابط-متجرك.netlify.app",`
3. انشر الموقع الأصلي كالمعتاد.

في المقابل، المتجر يحوي رابط «استوديو Triple A» (في القائمة والتذييل) يعيد الزائر إلى `STUDIO_URL` (المضبوط على `https://triple-a-a-a.netlify.app`)، ورابط «أعمالنا» إلى صفحة المعرض هناك.

## 10) إضافة المنتجات وتعديلها ونشرها وحذفها

افتح `admin.html` وسجّل الدخول.

**إضافة منتج:** «+ منتج جديد» ← اختر **النوع** فتتغير الحقول تلقائياً:
- **منتج مادي:** السعر، المصدر (مخزون خاص بكمية، أو مورّد خارجي «عند الطلب» بكمية اختيارية)، الشحن، المواصفات (سطر لكل مواصفة بصيغة `الاسم: القيمة`)، بيانات مورّد/تكلفة **خاصة** لا تظهر للزوار، خيارات (مقاس/لون/موديل).
- **منتج رقمي:** السعر، صيغة الملف، طريقة التسليم، تعليمات التحميل، الملف الخاص.
- **خدمة:** السعر (أو «ابتداءً من»، أو «عرض سعر فقط»)، ما يشمله العمل (سطر لكل عنصر)، مدة التنفيذ المتوقعة. بدون مخزون.

املأ الاسم **العربي** (إلزامي) والفرنسي والإنجليزي (اختياري؛ إن غابت لغة يعرض المتجر العربية). الرابط (slug) يُولَّد من الاسم الإنجليزي ويمكنك تعديله. ارفع حتى 8 صور (الأولى رئيسية؛ أزرار «تقديم/تأخير» للترتيب). فعّل «منشور» ليظهر للزوار، و«مميز» ليظهر في الصفحة الرئيسية.

**نصائح لإضافة 20–100 منتج بسرعة:** أنشئ الأقسام أولاً (تبويب «الأقسام»)، ثم أضف المنتجات بالترتيب. القائمة تدعم البحث وفلاتر النوع/الحالة/القسم وترقيماً (10 في الصفحة). من القائمة يمكنك **نشر/إخفاء** و**تمييز** بضغطة واحدة بدون فتح النموذج.

**تعديل:** زر «تعديل». **حذف:** زر «حذف» ← نافذة تأكيد ← يُحذف المنتج وصوره وبياناته الخاصة نهائياً (للإخفاء المؤقت استعمل «إخفاء» بدل الحذف).

ملاحظات: قيم الخيارات (مثل: أسود, أبيض) تُكتب مرة واحدة وتظهر كما هي في كل اللغات (أما **اسم** الخيار فبثلاث لغات). الحفظ يتم على عدة خطوات؛ إن فشل إنشاء منتج جديد في منتصف الطريق يتراجع النظام ويحذف ما أُنشئ.

## 10-ب) سجل الطلبات في لوحة الإدارة (اختياري)

**التفعيل:** نفّذ `supabase/migrations/005_orders.sql` في SQL Editor (بعد الملفات 001–003). بدونه يعمل المتجر كما كان تماماً، ويظهر تبويب «الطلبات» برسالة تطلب تنفيذ الملف.

**كيف يعمل:** عندما يضغط الزبون زر «إرسال الطلب عبر واتساب» (من السلة أو من صفحة المنتج) يُسجَّل في الخلفية: المرجع واللغة والمنتجات والكميات والخيارات والملاحظات. **لا تُرسَل أسعار ولا مجاميع**: دالة `create_order` في القاعدة تحسبها من جدول المنتجات وترفض المنتجات غير المنشورة والكميات فوق المخزون والخيارات غير الصحيحة. لا نجمع أي بيانات شخصية؛ تربط الطلب بالزبون من رسالة واتساب التي فيها نفس المرجع (`TA-YYMMDD-XXXX`).

**في لوحة الإدارة:** تبويب «الطلبات» بعدّاد أحمر للطلبات الجديدة (يتحدّث كل دقيقة مع إشعار عند وصول طلب)، فلتر بالحالة، تفاصيل كل طلب، تغيير الحالة (جديد ← مؤكد ← مكتمل / ملغى)، ملاحظة داخلية، وحذف بتأكيد.

**⚠ افهم هذه الحدود:**
- **«جديد» تعني أن الزبون ضغط الزر فقط**، وليس أنه أرسل الرسالة فعلاً ولا أنه دفع. قد ترى طلباً بلا رسالة واتساب مقابلة؛ والعكس لا يحدث إلا إن فشل التسجيل (وهو لا يمنع فتح واتساب).
- **المخزون لا يُخصم ولا يُحجز تلقائياً**؛ عدّله يدوياً بعد التأكيد.
- **يمكن لأي شخص إرسال طلبات وهمية** (الدالة عامة). وضعنا تحقّقات وحداً عاماً (60 طلباً/دقيقة)، لكنها ليست حماية كاملة من الإغراق؛ احذف الوهمي من التبويب. إن تفاقم الأمر نضيف Captcha أو حدّاً لكل جهاز.
- **اختبار:** اختُبر السلوك عبر Supabase وهمي في المتصفح؛ **دالة SQL نفسها لم تُنفَّذ على Postgres حقيقي** قبل تسليمها لك. أبلغ عن أي خطأ يظهر عند تنفيذ الملف.

**للإلغاء:** احذف وسم `<script src="js/admin-orders.js">` من `admin.html` (يختفي التبويب) ووسم `orders.js` من `cart.html` و`product.html` (يتوقف التسجيل). ولحذف الجداول: التعليق في أول `005_orders.sql`.

## 11) إعداد رقم واتساب

في `js/config.js`: `WHATSAPP_NUMBER: "212633740099"` (أرقام فقط بصيغة دولية، بدون `+` أو مسافات). الرقم الحالي هو الذي زودتني به (+212633740099) — **تحقق منه قبل الإطلاق** بفتح زر الطلب وإرسال رسالة اختبار.

الرسالة المولَّدة تحتوي: لغة الزبون، مرجع طلب محلي (`TA-YYMMDD-XXXX`)، اسم كل منتج ونوعه وخياراته وكميته وسعره ومجموعه الفرعي، ملاحظات الخدمة، المجموع (يُوسم «تقديري» إن وُجد سعر «ابتداءً من» أو عرض سعر)، وتنبيه أنها ليست تأكيد دفع ولا حجز مخزون. الأسعار تُجلب من القاعدة عند فتح السلة وتُعاد عند العودة للصفحة، ولا تُؤخذ من متصفح الزبون.

## 12) حل المشاكل الشائعة

| العَرَض | السبب والحل |
|---|---|
| «المتجر غير مُهيّأ بعد» | `SUPABASE_URL`/`SUPABASE_ANON_KEY` فارغان في `config.js`. |
| «تعذّر تحميل المنتجات» | تحقق من الرابط/المفتاح؛ نفّذت ملفات SQL الثلاثة؟ هل المشروع **متوقف (Paused)**؟ (الخطة المجانية توقف المشاريع الخاملة أسبوعاً — اضغط Restore في Supabase). افتح Console (F12) لرؤية الخطأ. |
| المتجر يعمل لكن لا منتجات | المنتج غير **منشور**، أو القسم **غير فعّال**، أو ينقصه اسم عربي/نص. |
| الدخول للإدارة يعطي «غير مخوَّل» | لم تنفّذ `create_first_admin.sql` ببريدك الصحيح. تحقق بـ `select * from admin_users;`. |
| «البريد أو كلمة المرور غير صحيحين» | أعد تعيين كلمة المرور من Authentication → Users. تأكد أن Auto Confirm مفعّل. |
| الصور لا تُرفع / خطأ صلاحيات | لم تنفّذ `003_storage.sql`، أو حسابك ليس في `admin_users`. |
| الصور لا تظهر عند الزوار | تأكد أن `product-images` **Public**. وإن استعملت دومين مخصصاً لـ Supabase حدّث CSP. |
| «تعذّر تحميل مكتبة Supabase» | لا اتصال بـ cdn.jsdelivr.net أو حاجب إعلانات. (يمكن تنزيل المكتبة ووضعها في `js/` وتغيير وسم script — لا تنسَ CSP.) |
| «انتهت الجلسة» | طبيعي؛ سجّل الدخول من جديد. |
| فشل الحفظ «slug مستخدم» | غيّر الرابط (slug) فهو فريد لكل منتج. |
| فشل بناء Netlify بسبب `generate-config` | أحد المتغيرات بصيغة خاطئة أو مفتاح سري؛ الرسالة في سجل البناء تشرح السبب. أزل المتغيرات واستعمل الطريقة أ. |
| تغييرات `config.js` لا تظهر | امسح كاش المتصفح (الملفات تُخزَّن مؤقتاً 5 دقائق). |

## 13) ما يحتاج إعداداً إضافياً أو يتجاوز حدود الخطة المجانية

**حدود Supabase المجانية** (تحققت منها من مصادر منشورة في 2026، لكن **راجع <https://supabase.com/pricing> فهي تتغير**؛ المصادر تختلف في حد التخزين بين 500MB و1GB): مشروعان، قاعدة 500MB، تخزين ملفات ~1GB، نقل بيانات 5GB شهرياً، 50,000 مستخدم نشط، والأهم: **المشاريع الخاملة تُوقَف بعد أسبوع بلا نشاط** (لا تُحذف بياناتها لكن المتجر يتعطل حتى تعيد تشغيله). المتجر المزدحم لن يتوقف، لكن المتجر الهادئ قد يتوقف؛ للإنتاج الجاد فكّر في خطة Pro (~25$/شهر) التي تلغي الإيقاف.

**Netlify:** الخطة المجانية تكفي لموقع ثابت صغير؛ راجع حدودها الحالية في netlify.com/pricing.

**ميزات غير مُنجزة عمداً (حتى لا نُوهمك بشيء غير موجود):**
- **الطلبات تُسجَّل فقط إن نفّذت 005_orders.sql** (القسم 10-ب)، ولا تُخصم الكميات تلقائياً ولا يُحجز المخزون؛ المخزون يعدّله المسؤول يدوياً بعد تأكيد الطلب على واتساب.
- **لا دفع إلكتروني.** الدفع يتم باتفاق مباشر على واتساب.
- **لا خريطة موقع (sitemap) تلقائية**؛ صفحات المنتجات ديناميكية. أضف sitemap يدوياً أو بأداة بعد اختيار الدومين.
- **التصفية في المتصفح** على كل المنتجات المنشورة (مناسب لـ 20–100، يتحمل حتى ~500). في لوحة الإدارة حد 1000 منتج.
- **التسليم الرقمي يدوي** (رابط مؤقت تنسخه أنت). لا تسليم تلقائي بعد الدفع.
- مكتبة Supabase تُحمَّل من CDN (jsDelivr) بنسخة مثبّتة. للاستقلال الكامل نزّلها محلياً.

## 12) إدارة المعرض (Portfolio) من لوحة الإدارة نفسها

تبويب **«إدارة المعرض»** في `admin.html` يدير مشاريع موقع المعرض (Triple A Studio) من نفس مشروع Supabase ونفس حساب المسؤول.

**التفعيل (مرة واحدة):** في SQL Editor نفّذ بالترتيب `supabase/migrations/006_portfolio.sql` ثم `007_portfolio_seed_taxonomy.sql` ثم (موصى به) `008_portfolio_seed_existing_project.sql`، ثم شغّل `supabase/verify_portfolio.sql` وقارن بالنتائج المتوقعة في تعليقاته. لا حاجة لأي إعداد تخزين: الصور تُرفع إلى الـbucket الموجود `product-images` تحت المسار `portfolio/` بسياساته الحالية.

**ما الذي يفعله التبويب:** قائمة وبحث وفلاتر، إضافة/تعديل/حذف (بتأكيد)، رفع غلاف ومعرض صور (تُصغَّر إلى 1600px وWebP)، اختيار الفئة والمجموعة، تمييز Featured، نشر/إخفاء، ترتيب العرض، ونصوص بثلاث لغات.

**الأمان:** القراءة العامة للمنشور فقط، والكتابة لمن تنطبق عليه `is_admin()` فقط (يفرضها Postgres). لإلغاء الميزة احذف وسم `<script src="js/admin-portfolio.js">` من `admin.html`.

**خارج نطاق الواجهة حالياً:** إدارة الفئات/المجموعات (عدّلها من Supabase → Table Editor، جداول `portfolio_categories` و`portfolio_collections`) وحقول `extra` (مراحل العمل/الأرقام/قبل-بعد) — تُحفظ كما هي ولا تُمسّ عند التعديل.

الاختبارات: `python3 tests/e2e_portfolio_admin.py` (65 فحصاً).
